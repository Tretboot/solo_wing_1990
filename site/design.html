DESIGN-BIBEL

Die visuelle & tonale DNA. Damit alle Agenten (und Menschen) dasselbe Ziel haben.

1. AUFLÖSUNG & RENDERING

VGA-Pixel-Look: Intern 640×400 via ctx.scale(2,2). Logik läuft in 320×200, Rendering skaliert 2×. image-rendering: pixelated, imageSmoothingEnabled = false. Text wird dadurch lesbar, ohne die Logik zu ändern.
Warum nicht 320×200 direkt? Zu pixelig zum Lesen. 640×400 ist der Sweet Spot: Pixel-Look bleibt, Text wird lesbar. (Nutzer-Feedback v0.4: "Der Text ist jetzt super lesbar.")

2. FARBEN

Die Palette ist bewusst 90s-Konsolen: dunkler Hintergrund, leuchtende Akzente, braune Cockpit-Elemente. Kein modernes UI.

System-Farben: Jeder Sektor hat eine Farbe. SEKTOR 7 = blau (kalt, militärisch), SEKTOR 9 = rot (heiß, instabil), SEKTOR 12 = neutral (zivil, staubig). Die Farbe durchzieht Bar, Briefing, Cockpit-Akzente.

3. FONT

Monospace, immer. 'Courier New', monospace. Größen: 5px (Labels), 6px (klein), 7px (Standard), 8-9px (Headers), 10-12px (Titel). Keine Proportional-Fonts. Das ist 1990, nicht 2025.

4. PIXEL-REGELN (Sprites)

Prozedural, kein PNG. Alle Sprites werden auf Offscreen-Canvases gezeichnet (16×16 Basis, Carrier 64×32). Skalierung via ctx.drawImage abhängig vom Z-Abstand. Warum? Kein Asset-Management, für Agenten gut editierbar, konsistenter Look.
16×16 Basis: Gegner-Schiffe sind 16×16 Pixel. Erkennbar als Raumschiff (Flügel, Rumpf, Triebwerk, Cockpit). Farben: rot/orange (Gegner), blau/weiß (Spieler), grau (Carrier).
Unscharfe Gesichter: Prozedural (mehrere überlappende Rechtecke + Alpha). Kein PNG. Für Funksprüche + Bar-Dialoge.

5. TONFALL (Text & Dialoge)

Deadpan, bürokratisch, 90s. Der Humor kommt aus dem Kontrast: kosmische Stakes vs. bürokratische Profanität. Nie wacky. Nie laut. Der Commander ist nicht böse, er ist nur müde.
Max. 2 Sätze pro Dialogzeile. Das ist Funkspruch, kein Roman. 90s-Referenzen: Fax, Modem, VHS, Windows 95, ISDN, AOL, Disketten.
"Die Gegenseite fliegt state of the art Technik. Von 1986."— COMMANDER, Briefing
"Es gibt keine Welle vier, Neun. Es gibt Welle drei und dann die Kantine."— SECHS, Bar
"Nächster."— COMMANDER, auf "Ist es furchtbar für ihn?"

6. META-HUMOR

Subtil, max. 1-2 Zeilen pro Screen. Der Witz ist, dass das Spiel seine eigenen Grenzen anerkennt. "Wer mehr Eingaben hat, schießt mehr Laser. Das ist kein Bug. Das ist Physik." "Das Flugzeug hat vier Waffenplätze. Diese Konsole hat acht."

7. COCKPIT (WC1-Stil)

Braune Panels, Gauges, Joystick, Beine. Top-HUD (FUEL/HP/WEAPONS), linke Waffentafel (Radar + Schild), rechte Targetting-Tafel (Score + Ziel), Eject-Button, Joystick + Hand, blaue Beine. Das "Ich sitze drin"-Gefühl ist das Ziel. (Referenz: Wing Commander 1.)

8. RÄUME (Fliegendes Dorf)

Jeder Raum ein eigener Artstyle. Prozedural, 20-40 Zeilen Canvas-Code. Kein einheitliches Design — die Bar ist warm (braun), die Kapelle dunkel (blau), der Friseur bunt (pink), der Maschinenraum grün. → Alle 10 Räume

9. AUDIO

Prozedural, Web Audio API. Keine Dateien. Laser (Square 800→200Hz), Explosion (Noise + Lowpass-Sweep), Schild (Sine 100Hz), Funk (Square 440Hz). TTS (Beta): Web Speech API, 10 Profile + Hash-Fallback, Stage-Directions werden ignoriert.

10. ORCHESTRIERUNG (Agenten-Regel, v0.6.2)

Lead Developer = Top-Level. Non-Thinking = Code. Lead Dev trifft nur Architektur-Entscheidungen (Spec, Schnittstellen, Edge-Cases) und reicht sie an einzelne Non-Thinking-Agenten weiter, die den Code liefern. Non-Thinking-Agenten reichen sich den Code hin und her (Pingpong) und härten ihn. Code Review gibt einen Score (1-5). Alles wird in Agent-Benchmarks gemessen. Warum? Lead Dev ist der beste Architekt, aber der langsameste Coder. NoThink Code crasht (Recursion) → mehr Limit. A/B-Test: nach 3 Runden Ø → NEU behalten oder rückgängig.
Referenz: WC1 NPC-Pilot-Intelligenz. Der echte WC1-Quellcode (wingleader.c) ist als Referenz für unsere Flug-KI gesichert: 2-Ebenen-KI (Mission → Taktik), DETERMINATION-Knob (KI-Schwierigkeit), "Kilrathi flee straight down" (Rout), Formation-Burst, Escort-Logik, Heat-Seeking-Missiles, Futurion (Alien wird real). → WC1_PCI_ANALYSE.md

11. DIE GOLDENE REGEL

"Es ist kein kaputtes Projekt, sondern ein poliertes Retro-Junk mit ein paar scharfen Ecken."— Code Review Agent, v0.1
